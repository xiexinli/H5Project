# 架构与分层边界（H5Project）

> 新增代码必须遵守本文件。评审时由 `web-review` 引用，改代码前由 `AGENTS.md` 会话启动顺序引入。

## 分层与依赖方向

```
views/ (页面)  →  components/ (展示组件)
      ↓                    ↓
composables/  ·  stores/ (状态)
      ↓
api/ · services/ (数据访问，唯一可发起请求的层)
      ↓
utils/ · types/ (纯逻辑 / 类型，与技术无关)
```

依赖方向自上而下，**禁止反向依赖与跨层直连**：

1. **页面/视图层（`views/`、`pages/`）**：负责布局、交互与路由；通过 composable / store 取数据，不直接调用 axios 或拼接请求。
2. **展示组件（`components/`）**：无业务副作用的可复用 UI；通过 props 进、emit 出，不直接访问全局 store 或发请求（容器型组件除外，需明确说明）。
3. **组合式函数 / 状态（`composables/`、`stores/`）**：承载页面逻辑与共享状态；调用 `api/services` 获取数据，不直接操作 DOM 或路由实例之外的环境。
4. **数据访问层（`api/`、`services/`）**：**唯一**允许发起 HTTP 请求的层；封装接口方法与 DTO 映射，返回类型化结果。
5. **纯逻辑与类型（`utils/`、`types/`）**：不依赖 Vue 运行时、组件库与请求库；可被任意层安全引用。

## 关键约定

1. **统一网络封装**：所有请求走统一的 axios 实例（含 baseURL、超时、请求/响应拦截器）。token 注入、错误归一化、loading 处理都在这里，不在业务层重复实现。
2. **错误处理**：请求错误统一归一化为可识别的错误结构（如 `{ code, message }`）；页面侧只做提示/兜底，不吞异常。
3. **状态管理**：Pinia store 用组合式写法；只在跨页面共享或需持久化时使用，页面局部状态留在组件内。
4. **路由**：页面级路由懒加载；鉴权路由走统一守卫，不在每个页面重复判断登录态。
5. **移动端适配**：尺寸单位统一走适配方案（vw/rem），安全区（刘海屏）用 `env(safe-area-inset-*)` 处理。
6. **组件库**：UI 一律用 Vant 4 组件；自定义样式避免覆盖组件内部类名，优先用官方 CSS 变量/主题定制。

## 禁止事项

- 视图层直接 `axios.get(...)` 或写死接口地址绕过 `api/` 层。
- 引入第二套状态管理、请求库或 UI 组件库与既有方案并行。
- 在 `utils/`、`types/` 中引入 Vue / Vant / DOM 依赖。
- 生产代码中混入 mock 数据或临时调试入口。
- 未按要求做跨模块 Vite 别名（`@/`）之外的深层相对路径穿透。
