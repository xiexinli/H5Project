# Web Verify

本仓库的 H5 验证工作流。

## 范围

- 全仓库的构建与验证行为。
- 尤其适用于 `src/` 下的页面、组件、composable、store、API 改动。
- 覆盖类型检查、构建、Lint 与单元测试的选择。

## 目标

- 选择能证明改动的最小验证。
- 区分真实失败与既有的/无关的告警。
- 复用本仓库已知可用的命令模式。

## 先读

1. 读 `references/task-map.md`。
2. 若是代码评审任务，与 `web-review` 合用。
3. 若是 Bug 或性能回退诊断，与 `diagnose` 合用。

## 核心规则

- 先看 diff，让验证范围与改动匹配。
- 对触及的文件先跑 `git diff --check`。
- 无关的告警/弃用信息视为背景噪声，除非构建失败或指向被改文件。
- 不因静态检查通过就宣称运行期正确；运行期行为需真机/浏览器验证时明确标注。

## 工作流

1. 检查改动文件并分类：
   - TS 逻辑 / composable / store
   - Vue 组件 / 模板
   - 样式
   - 仅测试
   - 构建配置（`vite.config.ts`、`tsconfig`、依赖）
2. 选择最小证据：
   - 类型检查：`pnpm type-check`
   - 静态检查：`pnpm lint`
   - 单元测试：`pnpm test`（改动的是被测逻辑时）
   - 构建：`pnpm build`（编译不足以证明，或改动构建配置时）
3. 对触及文件跑 `git diff --check`。
4. 运行 `references/task-map.md` 中的精确命令。
5. 汇报：执行的命令、是否通过、告警是既有噪声还是新失败。

## 汇报口径

- `Verified`：通过的确切命令。
- `Blocked`：确切命令与阻塞点。
- `Noise`：既有告警（仅相关时列出）。
- `Risk`：仍需人工或真机/视觉验证的部分。

## 护栏

- 有命令可验证时，不凭静态阅读宣称成功。
- 不一开始就升级；先用本地命令，确因环境缺失（如未装依赖）再说明阻塞。
- 不把全仓的告警/弃用刷成评审发现，除非由当前 diff 引起。
